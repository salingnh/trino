# Work Item 03 — Compiled Contract Schema and Immutable Runtime Model

## Goal

Define the versioned, immutable contract consumed by the connector. This contract is generated by the control plane and is not authored manually by SQL users.

## Dependencies

Work Items 01–02.

## Design boundary

The connector runtime consumes a **Compiled REST Contract**. It does not consume raw OpenAPI or arbitrary user-facing API definitions on workers.

Required transformation:

```text
User API Definition
  -> validation and capability inference
  -> Compiled REST Contract
  -> coordinator runtime model
  -> table handles and splits
```

The compiled contract must contain every execution decision needed by workers, except secrets and mutable runtime state.

## Top-level contract

Recommended shape:

```java
public record CompiledRestContract(
        int formatVersion,
        String contractId,
        String publishedVersion,
        ContractFingerprint fingerprint,
        Instant publishedAt,
        ImmutableList<CompiledRestSchema> schemas,
        ImmutableMap<String, String> metadata)
{
    public CompiledRestContract
    {
        // validate and defensively copy
    }
}
```

Rules:

- `formatVersion` is the connector contract format, not Trino version.
- `contractId + publishedVersion + fingerprint` uniquely identify immutable content.
- schema/table/column iteration order is deterministic.
- unknown metadata is retained only in a bounded string map if needed for diagnostics; it must not alter execution semantics.
- no secrets, tokens, passwords, private keys, raw authorization headers, or secret-store values.

## Schema and table model

```java
public record CompiledRestSchema(
        String name,
        Optional<String> comment,
        ImmutableList<CompiledRestTable> tables) {}
```

```java
public record CompiledRestTable(
        String name,
        Optional<String> comment,
        CompiledRestOperation operation,
        ImmutableList<CompiledRestColumn> columns,
        ImmutableMap<String, FilterBinding> filterBindings,
        ImmutableMap<SystemBindingRole, SystemBinding> systemBindings,
        ImmutableList<RequiredPredicateDefinition> requiredPredicates,
        PaginationDefinition pagination,
        Optional<ProjectionDefinition> projection,
        Optional<SortDefinition> sorting,
        GuardrailDefinition guardrails,
        Optional<String> authProfile,
        Optional<String> statisticsProfile) {}
```

One table represents one logical read operation. Do not merge list/detail operations unless the compiled contract explicitly provides deterministic routing and compatible row schemas.

## Operation model

```java
public record CompiledRestOperation(
        String operationId,
        HttpMethod method,
        String relativePathTemplate,
        Optional<String> requestContentType,
        ImmutableSet<Integer> successStatusCodes,
        Optional<String> responseContentTypePattern,
        JsonPointer rowPointer,
        Optional<JsonPointer> errorPointer,
        NotFoundBehavior notFoundBehavior,
        boolean readOnly,
        boolean idempotent) {}
```

Validation:

- method is GET or POST for MVP;
- POST requires `readOnly=true`;
- relative path begins with `/`, has no scheme/host/user-info, and cannot escape the configured base path;
- every path placeholder has exactly one request field binding;
- success status codes are explicit 2xx values or a validated range representation;
- `404 -> empty` is opt-in through `notFoundBehavior` and intended only for point lookup semantics;
- row pointer uses JSON Pointer syntax, not unrestricted JSONPath.

## Column model

```java
public record CompiledRestColumn(
        int ordinal,
        String name,
        String trinoType,
        JsonPointer responsePointer,
        boolean nullable,
        boolean hidden,
        Optional<String> comment,
        Optional<String> remoteFieldName) {}
```

Rules:

- ordinal is unique and contiguous within the table;
- names are unique case-insensitively under Trino identifier semantics;
- `trinoType` is parsed by coordinator through `TypeManager`; workers receive serializable type identity/column handles, not a mutable parser object;
- response pointer is relative to one row;
- hidden columns are reserved for input-only/system use and must be clearly distinguished from response fields;
- duplicate pointer mappings are allowed only when explicitly intentional and tested.

## Request fields and bindings

```java
public record CompiledRequestField(
        String name,
        RequestLocation location,
        String remoteName,
        Optional<JsonPointer> bodyPointer,
        String valueType,
        boolean required,
        RequestValueSource source,
```

Locations:

```text

HEADER
BODY
```

Sources:

```text
SQL_PREDICATE
SYSTEM

```

Authentication fields are never represented as SQL/request fields. Auth is resolved by profile.

Filter binding:

```java
public record FilterBinding(
        int columnOrdinal,
        FilterOperator operator,
        String requestField,
        Enforcement enforcement,
        CollectionSemantics collectionSemantics,
        NullSemantics nullSemantics) {}
```

`Enforcement` values:

```text
EXACT
APPROXIMATE
```

An approximate binding is a remote prefilter and must always leave the SQL predicate residual.

## System bindings

System roles include:

```text
LIMIT
OFFSET
PAGE
PAGE_SIZE
CURSOR
PROJECTION
SORT
SNAPSHOT_TOKEN
```

The contract must map roles explicitly. Runtime must never infer a system role from field names such as `limit`, `page`, `size`, or `q`.

## Pagination model

Use a sealed or tagged polymorphic model:

```java
public sealed interface PaginationDefinition
        permits NoPaginationDefinition,
                PagePaginationDefinition,
                OffsetPaginationDefinition,
                CursorPaginationDefinition,
                NextLinkPaginationDefinition
{
    PaginationType type();
}
```

Common fields belong in each concrete definition or a shared immutable value object:

- maximum page size;
- start page/offset;
- stop-on-empty behavior;
- maximum pages override bounded by catalog hard limit;
- total count/page pointer when provided;
- stable ordering declaration;
- consistency mode;
- repeated continuation detection settings.

Next-link definitions must state whether the link is read from body or RFC-compatible header metadata and whether relative links are allowed. Host/origin policy remains catalog security configuration.

## Guardrails

Contract guardrails may only reduce catalog limits:

```java
public record GuardrailDefinition(
        OptionalLong maximumRequests,
        OptionalLong maximumPages,
        OptionalLong maximumRows,
        OptionalLong maximumBytes,
        OptionalInt maximumSplits,
        OptionalInt maximumBatchSize,
        boolean requiredBoundedScan) {}
```

Effective limit is `min(catalog, contract, session)` where session can only reduce.

## Fingerprint

Fingerprint algorithm must be deterministic:

1. Parse contract into canonical model.
2. Serialize semantic fields in stable order using a documented canonical JSON writer.
3. Exclude transport metadata that does not affect execution only if explicitly listed.
4. Hash canonical bytes with SHA-256.
5. Represent as lowercase hexadecimal.

Do not fingerprint raw JSON bytes because whitespace/key order should not change identity.

## JSON compatibility policy

- Reject unknown `formatVersion` values.
- Within a supported format version, either reject unknown execution fields or configure the codec to fail on unknown properties. Silent ignore is not allowed for semantics-bearing fields.
- Adding optional fields with safe defaults requires a format compatibility note and tests.
- Renaming/removing fields requires a new format version or explicit migration adapter.
- Connector must log contract ID/version/fingerprint, never the complete contract at INFO.

## Validation API

Implement one validator that returns all deterministic failures where practical:

```java
public final class CompiledContractValidator
{
    public ValidationResult validate(CompiledRestContract contract);

    public void validateOrThrow(CompiledRestContract contract);
}
```

`ValidationResult` contains immutable errors and warnings with:

- stable code;
- JSON pointer into contract;
- safe human-readable message;
- table/operation identity when available.

Fatal examples:

- duplicate schema/table/column;
- unresolved request field;
- incompatible filter/request types;
- missing path binding;
- invalid row pointer;
- cursor definition without next-cursor pointer;
- page/offset strategy without appropriate system bindings;
- auth profile reference blank;
- contract guardrail greater than catalog guardrail after resolution;
- approximate binding marked as exact by contradictory fields.

## Tests

Create golden fixtures:

```text
src/test/resources/contracts/minimal-get.json
src/test/resources/contracts/post-cursor.json
src/test/resources/contracts/all-pagination-types.json
src/test/resources/contracts/invalid/*.json
```

Tests must cover:

- deterministic JSON round trip;
- deterministic fingerprint independent of input key order;
- exact failure pointer/code for every invariant;
- all pagination polymorphic variants;
- unknown format version;
- unknown field behavior;
- no secret-like keys/values in accepted contract model;
- stable equality/hash behavior after round trip;
- table/column order preservation.

Do not use snapshots that hide semantic changes without review. Expected contract JSON should be readable and version-controlled.

## Acceptance criteria

- Coordinator can deserialize a valid contract into a fully immutable model.
- Model contains no runtime clients, Trino sessions, Type objects, secrets, or mutable collections.
- Contract validation prevents every known ambiguous/unsafe state before metadata is exposed.
- Fingerprint is stable and verified by tests.
- Workers can receive only derived handles/splits, not the entire user definition.
- The model supports all MVP pagination families and exact/approximate enforcement.
