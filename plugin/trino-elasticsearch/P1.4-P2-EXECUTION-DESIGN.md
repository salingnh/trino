# Search execution and query-shape hardening

## Phase-start architectural audit

P1.4 and P2 extend the existing Remote Predicate IR, table handle, translation
enforcement and connector-scoped diagnostics. They do not introduce another
predicate planner, residual model, or metrics pipeline.

`SearchExecutionStrategy` owns a remote pagination context. `SearchExecution`
owns consumption, LIMIT termination, cancellation, failure accounting and
idempotent cleanup. Scroll and PIT implement the same contract. The page source
only decodes documents returned by the execution. P2 early termination uses this
contract without knowing the pagination mechanism. A response decoder converts
transport JSON into the existing `SearchDocument` model; alternative decoders do
not change column decoding or SQL NULL/array semantics.

Scroll remains the default and compatibility path. PIT is opt-in and must preserve
shard restriction, query, projection, sort, stable tie breaking and the latest PIT
identifier. A failed/expired context fails the query; reopening it would silently
change the snapshot. Never switch strategy after rows have been returned.

Normal exhaustion and pushed LIMIT close resources immediately, without counting
as cancellation. An early downstream close counts cancellation. Decode, fetch and
open failures close owned resources without masking the original exception.
Retries remain in the existing bounded HTTP backpressure layer.

Statistics render the authoritative handle IR only when enforcement is exact.
Candidate/approximate filters retain conservative unknown statistics. Statistics
requests remain timeout-bounded; large document counts prevent per-column scans.
No cache or configurable composite page size is added without measurements.
Aggregation has only one execution mode and needs no speculative strategy layer.

## Validation gates

- HTTP-backed lifecycle tests: open, pagination, latest context, LIMIT, exhaustion,
  early/repeated close, decode/fetch/cleanup failure and unchanged diagnostics.
- Response-decoder equivalence on nested values, arrays, missing/NULL, timestamps,
  binary, raw JSON, sort tokens and non-ASCII source bytes.
- ES7/ES8 correctness across predicates, projections, LIMIT/TopN, aggregation and
  statistics; benchmark pagination and decoding before enabling optimizations.
- AirStyle, focused tests, full connector tests and clean Error Prone verification
  locally before any push; CI afterwards. No phase completion inferred from an
  earlier SHA.

P3 sample/join remains research-only as specified by the roadmap. No unproven
sampling or join semantics will be enabled to make a checklist appear complete.

## Local implementation evidence (2026-09-06)

The complete module gate passed with 1,491 tests, zero failures/errors and 682
skips (680 inherited unsupported-capability cases, two explicit benchmark gates).
The final pre-commit gate, including subsequent hardening and both opt-in
benchmarks, passes with 1,498 tests, zero failures/errors and 680 inherited
unsupported-capability skips. AirStyle, Error Prone, ES7/ES8 integration, docs and
plugin packaging all pass. The committed SHA must pass verification before push;
the exact-SHA CI result is tracked separately on the PR.
Both ES7/ES8 PIT suites inherit the same full predicate/connector test hierarchy
as Scroll; their page size is 100 and their decoder is streaming. PIT/materialized
also passed both full suites before enabling streaming in those fixtures.

Two reproducible measurement entry points are opt-in, not timing assertions:

```bash
./mvnw -nsu -pl :trino-elasticsearch -Delasticsearch.benchmark=true \
  -Dtest=TestSearchExecutionBenchmark,TestSearchResponseDecoderBenchmark test
```

The strategy experiment loads 5,000 documents across three shards and checks exact
ID coverage without duplicates. Each strategy reads 5,103,890 source bytes with
54 search/page requests per round, plus its context management requests. Initial
ES7 timings were Scroll 1,026/679/398 ms and PIT 487/379/364 ms; ES8 timings were
Scroll 711/497/374 ms and PIT 409/386/322 ms. Order, warming, shared JVM heap and
Docker scheduling confound these small measurements: they do not justify changing
defaults or claiming a production-wide speedup. Logged heap endpoints are not peak
heap or allocation measurements. A further round delays consumption so each scan
takes over five seconds with a one-second keep-alive; both strategies on both ES
versions renew successfully and return every document.

The decoder experiment compares 100- and 1,000-hit pages in both execution orders.
For 1,000 hits a warmed reverse-order measurement was roughly 7.5 ms/materialized
versus 7.6 ms/streaming; other orders favored streaming. Streaming avoids retaining
the whole response tree but a universal speed/heap benefit is not established.
Both defaults therefore stay unchanged; both alternatives are explicit opt-ins.

P2 retains the fixed composite size (1,000) and adds no statistics cache. There is
no evidence here that another page size or a cache improves representative work.
Statistics cost remains bounded by request timeout, column limit and document
threshold. Partial responses remain unknown, and metadata lookup failures preserve
the available row estimate. Aggregation has one mode and no remote cursor to free;
close ends local pagination and failures cannot accidentally retry the page.

PIT protocol references: [pagination](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results)
and [context ownership](https://www.elastic.co/docs/api/doc/elasticsearch/v8/operation/operation-open-point-in-time).

## P3 disposition

No production sample or join pushdown is added. A document sampling algorithm must
first prove the requested Trino sampling semantics, including probabilities and
NULL/array handling; the roadmap intentionally leaves it research-only. Generic
joins remain engine-side with exact dynamic filters. Implementing either without
that proof would violate the existing architectural and correctness requirements.

## Response field-order hardening

A follow-up regression exposed a streaming cleanup gap: failure metadata before
`_scroll_id`/`pit_id` caused the decoder to throw before transferring context
ownership. Streaming now reads the complete valid envelope before rejecting
timed-out or shard-failed results. It still returns no partial page. Tests cover
both failure forms and both decoders, plus HTTP-backed PIT cleanup proving that
the latest ID is closed exactly once without reopening the query. Malformed or
truncated JSON still fails immediately; an ID that was never received cannot be
recovered by this client.
